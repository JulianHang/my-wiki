一、这三种范式在"思考"与"行动"的组织方式上有什么本质区别
1. ReAct：思考后行动，如果未完成目标，则将行动后的结果作为下一轮的输入，开始新的一轮思考-行动，直至达成目标。思考与行动交错执行，思考直接驱动行动。
2. Plan-and-Solve：整体规划后，按照计划行动，将上一步行动的结果告知到下一步行动，直到整体计划完成。
3. Reflection：初步执行任务后，对输出进行反思，提出与执行优化建议，接着对其进行下一轮的反思，直到"反思"认为已经是最优解了。

二、如果要设计一个"智能家居控制助手"（需要控制灯光、空调、窗帘等多个设备，并根据用户习惯自动调节），你会选择哪种范式作为基础架构？为什么？

- 使用ReAct作为基础架构，环境与人物是动态变化的，每执行一次行动后，便要思考下一步，随时因为环境和人物的变化，调整灯光、空调、窗帘等多个设备，比如到了夜晚自动打开灯光、打开哪里的灯光，随着人物移动到某一个房间、或者多个房间同时在使用，需要自动关闭和打开灯光，灯光的强度需要结合人物的使用场景等。固定场景下可以使用Plan-and-Solve架构，比如下班的时候默认打开客厅的灯光、空调冷风等一系列用户在该场景下习惯操作的设备。

三、是否可以将这三种范式进行组合使用？若可以，请尝试设计一个混合范式的智能体架构，并说明其适用场景

可以，首先使用Plan-and-Solve对整体计划进行任务拆解，接着采用ReAct对每个任务进行思考分析与执行，直到该任务完成，最后对该任务使用Reflection实行反思，以达到最优解。举例：北京旅游7天，整体预算5000，偏好历史文化，首先规划每一天的任务安排，比如第一天坐飞机...，接着按照预算、偏好设计每一天出行的方式、饮食、旅游景点等门票费用，为了让出行更加合理，对初步的任务分解进行提前30d的优化，比如哪一天哪一时刻订机票最便宜。

一、为 ReAct 智能体添加一个"计算器"工具，使其能够处理复杂的数学计算问题（如"计算 (123 + 456) × 789/ 12 = ? 的结果"）
```python
import ast
import operator

SUPPORTED_OPERATORS = {
    ast.Add: operator.add,
    ast.Sub: operator.sub,
    ast.Mult: operator.mul,
    ast.Div: operator.truediv,
}

def calculator(expression: str) -> str:
    """
    一个安全的计算器工具，支持基本的数学表达式计算。
    """
    print(f"🧮 正在执行 [Calculator] 计算: {expression}")

    def eval_node(node: ast.expr) -> int | float:
        if isinstance(node, ast.Constant):
            if isinstance(node.value, (int, float)):
                return node.value
            raise ValueError(f"非数字类型: {type(node.value)}")
        elif isinstance(node, ast.BinOp):
            left_val = eval_node(node.left)
            right_val = eval_node(node.right)

            if type(node.op) in SUPPORTED_OPERATORS:
                return SUPPORTED_OPERATORS[type(node.op)](left_val, right_val)
            raise NotImplementedError(f"不支持的二元运算符: {node.op}")
        elif isinstance(node, ast.UnaryOp) and isinstance(node.op, ast.USub):
            return -eval_node(node.operand)
        else:
            raise NotImplementedError(f"不支持的节点类型: {type(node)}")

    try:
        tree = ast.parse(expression, mode='eval')
        return str(eval_node(tree.body))
    except Exception as e:
        return f"计算时发生错误: {e}"


print(calculator("1 + 2 * 3"))
```

def _consecutive_failures(self) -> int:
    """计算连续失败次数（从后往前数）"""
    count = 0
    for f in reversed(self.failures):
        if f.step == len(self.failures) - count:  # 连续编号判断
            count += 1
        else:
            break
    return count

# ----> 换换成  --->
def _consecutive_failures(self) -> int:
    count = 0

    for record in reversed(self.call_history):
        if record.success:
            break
        count += 1

    return count

三、尝试设计一个"分层规划"系统:先生成高层次的抽象计划，然后针对每个高层步骤再生成详细的子计划。这种设计有什么优势？

通过高层的抽象可以指定做什么（What），而低层完成怎么做（How）。这样做有如下优点：

- 更高的复用性和模块化：低层会变成的更精细和更通用。
1. 更好的可读性和可维护性：高层的计划可以更加清晰和简洁，更容易理解和维护。
2. 良好的错误隔离：如果子计划执行失败，只需在局部重新规划即可，无需推翻整个计划。
3. 良好的异步和分布式支持：子计划可以并行执行，也可以在不同的节点上进行。
