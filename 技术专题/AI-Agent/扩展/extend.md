# 扩展

## 概念

### 注意力机制
词与词之间建立联系，彼此之间互相解释，丰富彼此的语义。大模型会将一段输入内容通过`分词器`划分成多个token来表示，同时将这些token转换成高纬度的向量，该向量通过矩阵计算出Q、K、V，其中Q表示当前向量（token）需要什么、K表示当前向量（token）能提供什么信息，V表示当前向量（token）提供的具体信息，接着让每一个向量的Q和所有向量的K做计算，得到一个相似度（相关性分数），把得到的相似度转换权重（注意力权重，是通过不断训练得到的），最后把每个K对应的V乘以对应的权重（加权求和），得到最终的一个结果，该结果就是当前token的注意力输出。接着将注意力输出经过`残差连接`（原始输入）和`归一化`（不重要）处理，生成新的表示，叫做隐藏状态（hidden state），它会作为下一层的输入，生成新的Q、K、V。对于隐藏状态，我们可以近似的理解为是包含当前层的所有上下文信息。


### Transformer-Decode流程
Transformer-Decode流程内部会有多个Decode Layer堆叠而成，每一层都包含注意力机制，主要是为了预测下一个token是什么，可以理解成下一次输出什么，上一层的输出会作为下一层的输入。在上面的注意力机制中，最终我们会拿到一个隐藏状态，该隐藏状态我个人理解，可以把它当作是包含所有token的上下文信息。LLM内部有一个词表，将隐藏状态映射到该词表中，可以得到词表中每个词的分数，分数越高，选中该词的概率就越高，接着在将该分数经过SoftMax转换成概率（0.01），最后按照不同的策略选择某一个词输出。


### KV Cache
在每一层注意力机制中，计算每个token的K、V，并将其缓存下来。后续生成新的token时，只需要计算新token自己的Q、K、V，然后将新的K、V追加到缓存中，用缓存里完整的K、V计算下一次。

### 模型参数量化
用更低精度的数据类型表示模型中的参数和计算结果，从而减少模型占用的存储空间和计算资源。好处是模型大小降低、GPU占用降低、推理速度加快，坏处是模型精度有所下降，数值可能存在误差。

### 模型参数蒸馏
学习已经较为成熟模型的核心内容，从而减少自身模型的计算，降低模型大小、GPU占用降低，坏处是成熟模型的错误或偏见可能会被继承。

### Prefill-Decode流程
Prefill阶段是一次性处理所有输入token，为每一层（Decode Layer）、每个token计算出K、V并存入缓存中。每一层的计算是并行计算的，每个token只能看到它之前的token。每一层都会计算所有的token，计算的维度可能不同，每一层生成的K、V也是不同的，因此缓存的K、V也是不同的，上一层计算后得到一个隐藏状态传递给下一层，层与层之间是串行的，上一层的输出作为下一层的输入参与当前层Q、K、V的计算（第二层）。取Prefill阶段上最后位置的隐藏状态计算得到第一个token，该token将作为Decode阶段的第一个输入。到了Decode阶段，拿着上面给的token按照注意力机制计算下一个token，每次只处理一个token。Prefill阶段和Decode阶段共用同一套Decode Layer，也就是说Prefiil阶段生成的KV会放入到缓存中，到了Decode阶段可以使用缓存中的KV。另外，Prefill阶段主要是计算所有token的Q、K、V，主要受限于算力（Compute Bound），而Decode阶段每次只需要计算新的单个token，但是该token需要与历史KV Cache挨个做计算，需要从显存上读取KV Cache，主要受限于带宽（Memory Bound）。

### 前缀缓存（Prompt Cache）
Prompt Cache指的是多轮对话中"重复"的Prompt，可以避免多次计算，主要优化的是TTFT（Prefill阶段），而非TPOT，但是如何定义"重复"，是Prompt Cache关键的地方，它要求连续且完全匹配的开头，相当于是逐token匹配，中间有token差异就会导致该位置之后的Cache失效。为了降低Cache失效的场景，从应用层角度出发，有以下几种优化手段：

- 提示词：固定内容放前面，动态内容放后面
- 工具列表永远不变
1. 涉及到状态变化的，可以使用多个工具来实现
2. OpenAI API的方式：固定工具集 + namespace（可选） + ToolSearch + 延迟加载工具 schema；Claude Code API的方式：工具名和描述 + ToolSearch + 延迟加载工具 schema
3. 消息追加，不修改已有内容
4. 单次对话不切换模型，用子代理隔离


### 上下文腐烂
随着上下文越来越长，模型对于早期信息的利用能力逐渐下降。

### 信息稀释
重要信息被次要信息、重复内容或无关内容包围，导致它在整体上下中的相对重要程序下降。

### 首字延迟（TTFT）
从用户发出请求开始，到模型生成并返回第一个输出token所经过的时间，该时长由Prefill阶段的耗时决定。

### 每Token延迟（TPOT）
生成后续每个token的平均时间，主要由Decode阶段的耗时决定。
