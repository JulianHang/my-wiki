# 入门

## Responses API

### 参数说明
介绍 Responses API 相关参数

#### 入参

- input： 用户提问的内容
- instruction： 系统提示词
- max_output_tokens： 控制输出的token数
- temperature 和 top-p：用于控制生成文本的多样性，数值越高，内容越多样，数值越低，内容越确定。为准确评估参数效果，建议每次只调整一个。
    - temperature：范围[0, 2)，侧重调整随机性。
    - top-p：范围[0,1)，通过概率阈值筛选回复。


## RAG

### 概念

- 检索（Retrieve）：根据用户的问题，从外部知识库中找到最相关的文档片段。
- 增强（Augment）：将检索到的文档片段与用户问题拼接在一起，构成增强后的提示词。
- 生成（Generate）：将增强后的提示词送入大模型，生成最终回答。


### 离线索引阶段
将所有的文档，切分成一个个的chunk（块），然后向量化为一串向量数字数组，保存到向量库中。

- 文档加载（Document Loader）：pdf、word、md、html等不同文档，使用不同加载器读取文档内容。
- 文档切分（Text Splitter）：将大文档切分成不同的chunk块。
- 向量化（Embedding Model）：将chunk块转换为向量数组。
- 向量库（Vector Store）：保存向量数据，提供对向量数据的CRUD操作。

### 在线查询阶段
用户问题 -> 向量化 -> 在向量数据库中检索相似文档（Retrieve） -> 将检索结果与问题拼接为增强提示词 -> 大模型生成回答。

- 查询向量化：用户请求会通过嵌入模型转换为向量。
- 检索向量库：将生成的查询向量与向量数据库进行比对，找到最相关的信息以解答该问题。
- 添加上下文：检索到的文档或文本片段会被整合到提示词中，从而使大模型基于这些信息生成回复。
- 生成响应：LLM将接收到的检索内容与用户问题进行分析，生成特定上下文的响应。
